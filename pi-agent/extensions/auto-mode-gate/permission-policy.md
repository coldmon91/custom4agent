# 자동 승인 정책 참조

`permission-policy.json`은 Auto 모드에서 AI 심사를 생략할 수 있는 툴·셸 명령 목록.
기본 파일은 기존 허용 항목을 유지하며, `orca`는 포함하지 않음.
목록에 없는 작업은 AI 심사 대상으로 전달.
Read 모드의 활성 툴 목록과 Write 모드의 동작은 이 설정과 별개.

## 필드

모든 필드 필수이며 알 수 없는 필드 허용 안 함.
`version`은 숫자 `1`.
목록은 중복 없는 이름 배열이며 빈 배열은 해당 목록을 비활성화.
공백·제어문자·경로 구분자를 포함한 이름은 유효하지 않음.
각 목록은 최대 512개, 파일은 최대 128 KiB.

### `tools`

- `readOnly`: 심사 없이 허용하는 읽기 전용 툴.
  `bash`, `powershell`, `edit`, `write` 등록 불가.
- `inRootWrite`: `path` 인자를 신뢰 디렉터리·민감 경로 검사 후 허용하는 툴.
  지원 값은 `edit`, `write`.
- `screenedShell`: 명령 내용을 해석한 뒤 허용 여부를 판단하는 셸 툴.
  지원 값은 `bash`.

### `shell`

- `readOnly`: 읽기 전용 명령 이름.
  위험 인자·환경변수·리다이렉션 검사는 계속 적용.
- `inRootWrite`: 경로 인자를 신뢰 디렉터리 검사 후 허용하는 쓰기 명령 이름.
- `builtins`: 허용된 셸 내장 명령 이름.
- `gitReadOnly`: 허용된 읽기 전용 Git 하위 명령.
- `gitInRootWrite`: 허용된 저장소 내부 변경 하위 명령.
  기본값은 `add`이며 게시·이력 변경 명령은 포함하지 않음.
- `gitRemoteReadOnly`: 허용된 `git remote` 인자.
  `null`은 인자 없이 remote 목록을 조회하는 경우.
- `npmReadOnly`: 허용된 조회용 npm 하위 명령.

`cd`, `command -v`, 조회용 `sed`, 업로드·인증·파일 출력 없는 `curl`의 조건부 처리는 코드에 유지.
셸 문법, 실행 래퍼 해석, 위험 인자 정규식, 민감 경로 검사도 코드에 유지.
설정은 실제 읽기 전용 동작이나 경로 제약을 보장하지 않으므로, `orca`·스크립트 실행기 등을 통째로 조회 목록에 등록하면 안전 검사가 우회될 수 있음.

## 반영과 오류

변경 여부는 수정 시각·상태 변경 시각·파일 크기·inode로 확인.
파일 변경은 다음 도구 호출에 반영되며, JSON 수정만으로는 `/reload` 불필요.
최초 코드 변경의 적용에는 새 Pi 세션 또는 `/reload` 필요.
`/automode`는 적용 파일의 경로와 설정 오류를 표시.

파일 누락·읽기 실패·JSON 문법 오류·잘못된 필드는 전체 자동 승인 목록을 비활성화.
이전의 허용 목록을 계속 사용하거나 오류가 있는 항목만 부분 적용하지 않음.
일반 작업은 AI 심사를 거치며, AI 심사도 불가능하면 사용자 승인 요청.
UI가 없는 세션에서 사용자 승인이 필요한 작업은 거절.
유효한 파일로 복구하면 다음 호출부터 자동 승인 목록 복원.

## 정책 변경 보호

`permission-policy.json`을 직접 수정하거나, 정책 파일을 참조하는 읽기 전용으로 입증되지 않은 명령은 AI 심사보다 먼저 사용자 승인 요청.
정책 파일을 가리키는 심볼릭 링크도 검사.
정책 파일을 읽거나 `git diff`로 조회하는 작업은 계속 자동 승인 가능.
복사·스테이징처럼 정책 파일과 함께 등장하는 쓰기 작업도 보수적으로 승인 요청할 수 있음.

임의 스크립트 내부에서 숨겨진 경로를 계산하는 등 일반적인 파일 접근을 완전히 격리하는 샌드박스는 아님.
사용자가 직접 설정을 편집하는 작업에는 Pi 도구 호출 승인 절차가 적용되지 않음.
