# Pi 작업 디렉터리 밖 일반 쓰기 — 승인된 설계

> 상태: 구현하지 않음. 승인 창 대신 분류기의 allow를 yes로 실행한다. hard_deny만 거절한다.
> 아래 폴더 등록 설계는 그 결정 전 내용이며, 승인 창을 다시 켜기 전에는 따르지 않는다.


## 목적과 범위

작업 디렉터리 밖 일반 쓰기가 같은 폴더에서 반복해서 승인 창을 띄우는 문제를 줄인다.
검사기가 이미 안전한 쓰기로 읽는 명령에 한해, 사용자가 고른 폴더의 다음 일반 쓰기는 다시 묻지 않는다.
사용자에게 보이는 말에는 빠른 경로를 쓰지 않는다.
코드 안의 fast path라는 이름은 유지한다.

포함:

- 검사기가 경로만 막아서 자동 승인하지 못한 일반 쓰기
- 그 쓰기에 대한 이번만 승인, 폴더 등록, 거절
- 등록한 폴더를 `trusted-roots.json`에 추가

제외:

- `python3`, `ssh`, `rm`처럼 검사기가 읽지 못하는 명령. 지금처럼 분류기 심사
- 분류기 실패, 분류기 거절, 정책 파일 변경 심사
- `~/Documents`처럼 넓은 폴더의 등록
- 명령 이름을 허용 목록에 추가하는 일
- 등록 뒤 git commit

## 일반 쓰기

일반 쓰기는 각 쓰기 파일의 바로 위 폴더를 신뢰 디렉터리에 넣으면 기존 자동 승인이 되는 쓰기이다.
그 폴더를 넣어도 자동 승인이 되지 않으면 일반 쓰기가 아니다.
제안하는 폴더는 그 바로 위 폴더가 아니라, 아래 규칙의 홈 바로 아래 폴더이다.

일반 쓰기가 아닌 예:

- 허용 목록에 없는 명령. `python3`, `node`, `ssh`, `rm`, `git commit`
- 민감 경로, `.git`, 셸 PATH 위 쓰기, 자동 승인 정책 파일
- `cd`와 쓰기가 한 명령에 있는 경우
- 검사기가 명령 줄을 읽지 못하는 경우

셸과 `edit`·`write` 도구를 같은 기준으로 본다.
쓰기 목적지는 기존 검사기가 쓰는 경로 해석을 재사용한다.
등록할 폴더 이름은 사용자가 쓴 경로를 `~`와 현재 디렉터리 기준으로 펼친 뒤의 경로에서 뽑는다.
심볼릭 링크가 가리키는 실제 위치로 바꾸지 않는다.
폴더가 아직 없어도 된다.

## 제안하는 폴더

홈 바로 아래의 첫 폴더만 제안한다.
`~/session-records/dev/오늘/overview.md`의 제안은 `~/session-records`이다.

다음이면 등록을 제안하지 않는다.

- 목적지가 현재 사용자 홈 아래가 아님
- 한 명령의 목적지들이 서로 다른 홈 바로 아래 폴더를 가리킴
- 그 폴더 이름이 넓은 폴더 목록과 대소문자 없이 같음

넓은 폴더 목록은 `Documents`, `Desktop`, `Downloads`, `Library`, `Movies`, `Music`, `Pictures`, `Public`이다.
홈 자체, `/`, `/Users`는 제안하지 않는다.

## 구성과 흐름

1. 기존 자동 승인이면 그대로 실행한다.
2. 정책 파일 변경이면 지금처럼 사용자 승인만 묻는다. 폴더 등록은 없다.
3. 일반 쓰기이고 폴더만 빠져 있으면 분류기를 부르지 않는다.
4. 등록 가능한 폴더가 하나면 셋 중 하나를 고른다.
5. 등록 가능한 폴더가 없으면 이번만 승인과 거절만 묻는다.
6. 일반 쓰기가 아니면 지금처럼 분류기로 간다. 등록 선택은 없다.

판정은 게이트가 한다.
창은 지금처럼 `tool-mode-cycle`이 띄운다.
게이트는 UI를 직접 부르지 않는다.

셋 선택 창:

- 제목: `자동 모드 · 승인 필요`
- 본문에 이유 `작업 디렉터리 밖의 일반 쓰기입니다.`
- 본문에 대상 폴더. 예: `~/session-records`
- 본문에 `민감한 파일, .git, PATH 위 쓰기는 계속 심사합니다.`
- 선택: `이번만 승인`, `이 폴더의 일반 쓰기는 다음부터 승인 없이`, `거절`

둘 선택 창은 기존 예/아니오 창을 쓴다.
본문에 같은 이유와 쓰기 파일 경로를 모두 보이고, 질문은 `이번만 승인할까요?`이다.
등록 문구는 넣지 않는다.

취소와 거절은 같다.
파일을 바꾸지 않고 호출을 막는다.
막힌 이유의 규칙은 `Outside Root Write`이고, 이유는 `작업 디렉터리 밖의 일반 쓰기를 승인하지 않았습니다.`이다.
기존 거절과 같이 규칙과 이유를 남겨, 같은 호출을 그대로 다시 시도하지 않게 한다.

## 등록

등록을 고르면 `tool-mode-cycle`이 `trusted-roots.json`의 `roots` 끝에 그 항목만 추가한다.
저장 형태는 `~/session-records`처럼 홈 기준 한 단계이다.
`_readme`와 기존 항목, 모르는 필드는 유지한다.
`~/session-records`와 그 절대 경로는 같은 폴더로 보고, 이미 있으면 추가하지 않는다.
임시 파일에 쓰고 같은 디렉터리에서 교체한다.
git commit은 하지 않는다.

이번만 승인과 거절은 파일을 쓰지 않는다.
등록에 성공하면 이번 호출도 실행한다.
다음 호출부터 그 폴더 안 일반 쓰기는 기존 자동 승인을 탄다.
JSON 변경은 재시작이나 `/reload` 없이 다음 호출에 반영된다.
이 설계의 코드 변경은 새 세션 또는 `/reload`가 필요하다.

## 실패

UI가 없으면 등록하지 않고 호출을 거절한다.
JSON을 읽지 못하면 파일을 덮어쓰지 않고, 이번 호출은 실행한다.
등록 쓰기가 실패해도 이번 호출은 실행한다.
실패는 알림으로 알리고, 폴더가 등록되지 않았다고 말한다.
모델이 정책 파일을 고쳐 등록을 대신하게 하지 않는다.

## 단위

- `registration-offer.ts`: 일반 쓰기인지, 제안 폴더가 있는지만 판정
- `trusted-roots.ts`: 기존 내용 유지하며 루트 하나 추가
- `approval-prompt.ts`: 둘 선택·셋 선택 문구
- `gate.ts`: 일반 쓰기면 분류기 전에 질문 결과 반환
- `tool-mode-cycle.ts`: 창을 띄우고, 등록 선택 때만 파일 추가

## 검증

- `cat > ~/session-records/.../overview.md`는 `~/session-records` 등록을 제안하고 분류기를 부르지 않음
- `cat > ~/Documents/.../notes.md`는 이번만 승인만 묻고 등록 선택이 없음
- `python3`로 `~/session-records`를 고치는 명령은 등록 선택이 없고 분류기로 감
- 민감 경로와 `.git` 쓰기는 폴더를 추가해도 자동 승인이 되지 않아 등록 대상이 아님
- 한 명령이 `~/session-records`와 `~/workspace`에 같이 쓰면 등록 선택이 없음
- 이번만 승인은 파일을 쓰지 않고 실행
- 거절과 취소는 파일을 쓰지 않고 차단
- 등록은 `roots` 끝에 `~/session-records`를 더하고 `_readme`와 기존 항목을 유지
- 이미 있는 폴더는 다시 추가하지 않음
- 깨진 JSON은 덮어쓰지 않고, 이번 호출은 실행하며 등록 실패를 알림
- UI가 없으면 파일을 쓰지 않고 거절
- 등록 뒤 같은 폴더의 `cat >`는 자동 승인
