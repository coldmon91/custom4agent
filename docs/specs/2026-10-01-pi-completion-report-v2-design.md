# Pi 작업 완료 보고 개정 설계

## 목적과 범위

작업 목적, 결과의 원인, 실패 원인까지 보고하도록 `Completion Report` 섹션 교체.
기존 4요소(변경 내용, 방식의 이유, 사용자 영향, 남은 일)에는 작업 동기와 결과의 원인 항목 부재.
기존 생략 규칙상 변경 없이 실패한 시도는 보고 대상 외.
변경 대상은 `pi-agent/APPEND_SYSTEM.md` 의 `Completion Report` 섹션 한정, 나머지 섹션 보존.
공통 `AGENTS.md`, 확장 코드, `pi:agent` skill 의 위임 프롬프트 변경은 제외.

## 보고 구성

작업 → 방법 → 결과 → 변경점 또는 실패 원인 → 다음 할 일, 다섯 절 고정.

| 사용자 요구 | 담당 절 |
|---|---|
| 무슨 작업을, 왜 | 작업 |
| 어떤 방법으로, 그 방법의 이유 | 방법 |
| 결과, 그 결과의 이유 | 결과 |
| 성공 시 변경점 | 변경점 |
| 실패 시 실패 이유 | 실패 원인 |
| 다음 할 일 | 다음 할 일 |

방법의 이유는 설계 선택의 근거, 결과의 이유는 증거 기반 원인으로 분리.
기존 지침이 방식의 이유에서 문제의 원인을 배제한 목적(두 이유의 혼동 방지)은 절 분리로 유지.
부분 성공은 변경점과 실패 원인을 별도 절로 함께 기재, 병합 금지.
보고 대상은 변경을 시도한 모든 작업이며, 질문·조회·읽기 전용 조사만 제외.

지침은 추상 설명 대신 고정 양식으로 제시.
양식은 부록의 다른 섹션과 같이 영어(`Task`, `Approach`, `Result`, `Changes`, `Failure Cause`, `Next` 및 항목 `What`, `Why`, `How`, `Verdict`, `Verified`, `Impact`, `Cause`, `Evidence`, `Tried`, `State`)로 작성하고, 출력 시 사용자 언어로 번역.
작은 변경도 양식의 줄을 생략하지 않고 문장 길이만 축약하며, 특히 `Why` 줄은 필수.
영어 양식 전환 후 low 3회 재검증 결과 8, 8, 8점이며, 번역된 제목 표기에 소폭 편차(`방법`/`접근`, `근거`/`증거`) 존재.
추상 설명만 둔 첫 개정안에서 이유 항목이 9회 모두 누락되어 양식 방식으로 전환.

## 기존 지침에서 유지한 규칙

- 파일을 `path:line` 과 핵심 변경으로 표기, diff·도구 출력 재현 금지
- 실질적 트레이드오프가 있을 때 기각한 대안 명시
- 동작 무변경 시 명시, 미검증 범위 명시
- 남은 일이 없으면 없음으로 명시, 후속 작업 창작 금지
- 길이만 축약하고 요소는 생략 금지

## 기존 지침에서 바뀐 규칙

- 변경 없이 실패하거나 중단된 시도도 보고 대상
- 단일 파일 변경의 문장형 보고 허용 규칙 삭제, 절 제목 항상 표시
- 문제의 원인을 결과 절에서 명시적으로 요구

## 검증 기준

| 사례 | 기대 동작 |
|---|---|
| 성공한 변경 | 다섯 절, 변경점에 파일·영향·검증 결과 |
| 변경 없이 실패 | 보고 생략 없이 실패 원인의 근거·시도·잔여 상태 |
| 부분 성공 | 변경점과 실패 원인 모두 기재 |
| 한 줄 수정 | 절 생략 없이 절마다 한 줄 |
| 남은 일 없음 | 다음 할 일에 없음 명시 |
| 질문·조회 | 완료 보고 미적용 |

정적 검증은 다른 섹션 무변경, `Task Execution` 및 `Self-Service Before Handoff` 의 보고 규칙과의 모순 여부, `git diff --check` 확인.
행동 검증은 새 Pi 세션에서 실제 작업으로 확인하며, 정적 문구 검증을 행동 검증 통과로 간주하지 않음.

## 행동 검증 결과 (2026-10-01)

조건: `openai-codex/gpt-6.1-sol`, 부분 성공 과제(수정 가능한 `calc.py`, 부재한 `legacy.py`), 실행 전 고정한 8개 항목 채점.

| 지침 | thinking | 회차별 점수 | 평균 |
|---|---|---|---|
| 추상 설명 개정안 | low | 4, 1, 1 | 2.0 |
| 추상 설명 개정안 | medium | 0, 2, 1 | 1.0 |
| 추상 설명 개정안 | high | 1, 1, 3 | 1.7 |
| 고정 양식 개정안 | low | 8, 8, 8 | 8.0 |

thinking 수준 간 차이는 수준 내 편차보다 작아 준수율과의 상관 미확인.
양식 전환 후 low 에서 전 항목 충족, 보고 분량 약 2배, 소요 시간 34 ~ 46초로 변화 미미.
한계: 수준당 3회, 과제 1개, 모델 1개, 채점자 1인이며 채점 항목이 양식 항목과 대응해 양식 채움 여부 측정에 가까움.
`pi -p` 는 stdin 이 TTY 가 아니면 EOF 까지 대기하므로(`dist/main.js` `readPipedStdin`), 인자로 프롬프트를 넘기는 실험 실행은 `< /dev/null` 필수.

## 영향과 적용

`~/.pi/agent` 가 이 저장소의 `pi-agent` 를 가리키므로 Pi 전역 세션에 영향.
`pi -p` 위임 실행도 같은 부록을 읽지만, `pi:agent` skill 의 `[출력 형식]` 이 다른 절 구성을 지정하므로 위임 실행 보고는 그 형식을 따를 가능성 존재.
보고 분량 증가로 응답 토큰 소폭 증가.
지침 변경만으로 모델의 준수를 강제하지 않음.
