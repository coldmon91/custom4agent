# Pi 자동 승인 목록 JSON 분리 — 승인된 설계 기록

## 목적과 범위

사용자가 승인한 기존 허용 범위 유지 및 허용 목록 JSON 분리 구현.
Auto 모드의 툴·셸 명령·하위 명령 목록을 `permission-policy.json`으로 이동.
Read/Write 모드의 활성 툴 관리, 기존 승인 문구 작업, 분류 모델·신뢰 디렉터리 설정 변경은 제외.
`orca` 등 신규 허용 항목 추가는 제외.

## 구성과 흐름

1. `permission-policy.ts`가 JSON 전체를 검증하고 툴·셸 목록을 제공.
2. `fast-path.ts`와 셸 검사기가 같은 호출의 검증된 정책을 사용.
3. 경로 해석·민감 경로·위험 인자·셸 문법·실행 래퍼 처리는 기존 코드 유지.
4. 정책 파일 변경 가능성이 있는 작업은 AI 심사보다 먼저 사용자 승인.
5. `/automode`에서 정책 파일 위치 및 오류 확인 가능.

`permission-policy-protection.ts`는 정책 경로·심볼릭 링크·명령 참조 판별 담당.
Git staging은 읽기가 아니지만 기존 자동 승인 동작 유지.
정책 조회와 정책 변경 판별은 동일한 검사기를 재사용.

## 설정 반영과 실패 처리

유효한 설정은 파일 메타데이터가 변경될 때 재검증하고 다음 호출에 적용.
누락·읽기 실패·문법 오류·스키마 오류 발생 시 자동 승인하지 않는 보수적 기본값 사용.
하드코딩된 허용 목록의 복제나 이전 설정의 묵시적 재사용 없이 일반 작업을 AI 심사로 전달.
정책 오류는 `/automode`에 표시.
UI 없는 세션에서 정책 수정은 차단.

정책 보호는 경로·명령 참조 검사이며 OS 파일 접근 샌드박스는 아님.
실행 중인 Pi에 자동으로 `/reload`를 보내지 않음.
`~/.pi/agent`는 이 저장소의 `pi-agent`를 가리키므로 별도 복사 없이 새 세션에서 코드 사용 가능.
